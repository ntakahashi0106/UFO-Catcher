# HASHI — 橋渡しクレーンシミュレーター

ブラウザで遊べる橋渡し式のUFOキャッチャーです。three.jsで描画し、Rapier 3Dで景品・2本のバー・アームの接触を計算します。

## 起動

Node.js 20.19以上、または22.12以上を使用します。

```sh
npm install
npm run dev
```

表示されたローカルURLを開きます。同じWi-Fi上のスマートフォンからは、ターミナルに表示されたNetwork URLを横持ちで開いてください。WindowsのファイアウォールやWi-Fiの端末間通信設定によって接続できない場合は、公開URLを使用してください。

```sh
npm test
npm run build
npm run preview
```

`dist/`は静的ホスティングにそのまま配置できます。

## GitHub Pagesで公開

このゲームはサーバーを必要とせず、GitHub Pagesで公開できます。GitHub Freeでは公開リポジトリを使用します。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. `main` または `master` へプッシュすると、`.github/workflows/pages.yml` が依存関係のインストール、物理テスト、ビルドを実行します。既定ブランチの成果物が公開されます。
3. **Actions → Deploy game to GitHub Pages** の完了後、**Settings → Pages** に表示されるURLを開きます。手動で再公開する場合は **Run workflow** を実行します。

URLは通常 `https://<ユーザー名>.github.io/<リポジトリ名>/` です。ビルド時のアセット参照を相対パスにしているため、リポジトリ名を変更しても同じワークフローを使用できます。スマートフォンでもURLを開き、横持ちでプレイしてください。以降は既定ブランチへのプッシュで自動更新されます。

設定の詳細は[GitHub Pages公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)を参照してください。

## アプリとして追加・オフラインで遊ぶ

公開URLを開き、画面上部の「アプリに追加」を選ぶと、ホーム画面やデスクトップからHASHIを起動できます。

- **Android / PCのChrome・Edge**: 画面の追加ボタンからインストールします。案内が表示されない場合は、ブラウザのメニューから「アプリをインストール」または「ホーム画面に追加」を選びます。
- **iPhone / iPad**: Safariで開き、共有ボタン →「ホーム画面に追加」→「追加」を選びます。追加後はホーム画面のHASHIから横持ちで起動します。
- **MacのSafari**: ブラウザの共有メニューから「Dockに追加」を選びます。

最初はオンラインで読み込み、オフライン準備完了の表示まで待ってください。ゲーム本体・物理エンジン・アイコンをまとめて端末に保存した後は、同じブラウザまたは追加したアプリでオフラインでも遊べます。保存領域を消去した場合やOSが保存データを整理した場合は、オンラインで再読み込みしてください。記録はブラウザ／アプリごとの端末内に保存されます。

更新版の準備ができると画面に案内します。「更新して再起動」を選んだ時に再読み込みするため、プレイ中に自動でリセットされることはありません。ページを開き直した場合も、更新を選ぶかHASHIのすべての画面を閉じるまでは、保存済みの同じバージョンを使います。HTMLとゲーム本体のバージョンが混ざらないため、通信が途中で切れても保存済みのゲームを起動できます。初回読み込みが中断した場合は全ファイルの保存完了までオフライン準備完了を表示しません。

PWAの動作確認は `npm run build` → `npm run preview` で行います。開発用の `npm run dev` ではService Workerを登録しません。公開時にはHTTPSが必要です。アイコンは `npm run icons` で再生成できます。

## 操作

起動時に「スタンダード」（380 g）、「薄型ボックス」（300 g）、「トールボックス」（460 g）から選びます。形・重さ・摩擦・慣性がそれぞれ異なり、自己ベストは箱ごとに保存します。前回選んだタイプを次回の初期選択に使います。プレイの合間に操作パネルの「箱を変更」で選び直すと、景品の位置と挑戦回数がリセットされます。

| 操作 | PC | スマートフォン（横持ち） |
| --- | --- | --- |
| アーム位置 | WASD / 矢印キー | 矢印ボタンを長押し |
| キャッチ | Space / キャッチする | キャッチする |
| 視点変更 | カメラボタン / 画面ドラッグ | カメラボタン / スワイプ |
| 景品リセット | R / 景品を置き直す | 景品を置き直す |

キャッチは下降→閉じる→持ち上げる→開くの順に自動進行します。景品の位置と姿勢は次のプレイに引き継ぎます。箱が受け皿へ実際に接触すると獲得です。サウンドは初期状態でオフ、自己ベストはブラウザ内に保存します。

操作ボタンではダブルタップによる画面拡大を抑え、キャッチ・リセットなどの連続実行も防ぎます。移動ボタンは短い連続タップと長押しの両方で位置を調整できます。

操作パネルの「パワー」または設定ボタンから、アームパワーを20〜200％の範囲で10％刻みに変更できます。「弱め40％」「標準100％」「強め180％」のプリセットもあります。100％が従来の強さです。閉じる・持ち上げ時に保持する力の上限を変えるため、箱の重さや爪の掛かり方によって滑り方が変わります。弱くしても開く動作は保たれます。

変更はキャッチ動作の合間にでき、箱の位置と挑戦回数はそのままです。設定はこの端末に保存され、リセットや箱の変更後も引き継ぎます。自己ベストは箱とパワーの組み合わせごとに保存し、既存の記録は100％として引き継ぎます。挑戦の途中でパワーを変えた場合は記録対象外になり、「景品を置き直す」で計測を再開します。

まずは左右を中央に保ち、真上・側面のカメラを見ながら奥行きを少しずらすと、箱を傾ける動きを確認できます。

## 物理とモデル

- 固定1/120秒で剛体シミュレーション。景品の重量、角丸の接触形状、摩擦、慣性、CCDを使用します。
- 左右のアームは本体の中心付近にある回転ジョイントで接続し、支点から離れずに開閉します。角度を制御するトルクには上限があり、景品に押し返される動きも物理計算します。箱の固定、キャッチ確率、回数に応じた強制移動はありません。
- 箱・アーム・円柱バー・受け皿・筐体壁の接触を計算します。
- 実機そのものの寸法やモーター特性を測定した再現ではなく、橋渡しの挙動を遊びやすく調整したシミュレーションです。紙箱の変形、柔軟な配線、実機のアーム機構の全関節までは再現していません。
- 筐体、景品、アーム、文字はすべてパラメトリックなthree.jsジオメトリです。Blenderモデルや画像テクスチャは不要でした。

## 構成

- `src/main.js`: 操作、プレイ進行、サウンド、記録
- `src/physics.js`: Rapierによる剛体・モーター・接触・獲得判定
- `src/scene.js`: 筐体モデル、描画、照明、カメラ
- `src/claw.js`: 見た目と物理演算で共用するアーム形状・回転支点
- `src/prizes.js`: 箱の種類・形・重量・摩擦と下降位置
- `src/arm-power.js`: アームパワーの範囲・プリセット・記録の条件
- `src/input.js`: 連続操作とダブルタップの制御
- `src/pwa.js`: インストール案内、オフライン準備、更新の制御
- `scripts/build-pwa.mjs`: ビルド成果物を一括保存するService Workerの生成
- `src/config.js`: 寸法・重量・移動範囲
- `src/style.css`: PC・スマートフォン横持ちの画面レイアウト
- `tests/physics.test.js`: 安定性、重力、獲得、再挑戦、再現性、筐体内への収容、リセットの検証

WebGL 2とWebAssemblyに対応した現行ブラウザが必要です。負荷が高い場合は設定から描画品質を「軽量」にしてください。
